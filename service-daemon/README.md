# Optional Windows service

This standalone Rust process uses the shared scanning engine without Tauri. It is **not enabled by the GUI**, not a minifilter, not pre-execution protection, and does not remove, quarantine, or block files. A notify user-mode watcher queues created/modified `.exe`, `.dll`, `.msi`, `.bat`, and `.ps1` paths after two quiet seconds. Access/remove events and the service data directory are ignored. Watch events never initiate a full-root scan: full scans run at startup and on the configured interval only. No network listener, IPC command server or user-controlled scan requests are exposed.

Build with `cargo build --release --manifest-path service-daemon/Cargo.toml`. Review the executable, then explicitly run [install.ps1](./install.ps1) from elevated **Windows PowerShell 5.1**, passing `-BinaryPath` to that release executable. The installer creates fresh directories under Program Files/AegisSecurity and ProgramData/AegisSecurityService with SYSTEM/Administrators-only ACLs, registers a manual-start LocalSystem service, and leaves it stopped. The service data directory is separate from the GUI vault. Existing destination directories are refused, including retained directories after uninstall: review them manually. No install or service-start operation is performed by a normal app build.

An administrator must edit `%ProgramData%\AegisSecurityService\service.json` before starting the service:

```json
{"roots":["C:\\Users"],"interval_seconds":3600,"workers":2,"watch":true}
```

Choose local absolute directory roots (1–32), interval 60–604800 seconds and 1–4 workers. Unknown settings are rejected. Configuration is read at startup; restart after changes. Then run `Start-Service AegisSecurity`. Findings and scan errors go to the protected `findings.jsonl` in the same data directory. Logs contain local file paths and hashes; review and archive them as administrator. The log is capped at 10 MiB: before a record would exceed the cap, existing records are discarded by truncating the open protected file handle. Oversized individual records are omitted; no history archive is retained automatically. [uninstall.ps1](./uninstall.ps1) stops and removes only SCM registration, retaining data and executable.

The service checks the installed executable and parent directories below Program Files, configuration and data-directory owner/DACL, rejects write grants to identities other than SYSTEM/Administrators, and rejects reparse points. Unsupported ACL entries fail closed. These strict checks may reject installations with custom enterprise ACLs. Reparse entries are excluded from traversal. Before analysis, the service holds parent-directory handles through the engine's `lock_parents` function, preventing ancestor rename/reparse replacement until analysis finishes. This does not provide kernel execution blocking or a guarantee that a file cannot change after analysis. No filesystem integrity or comprehensive malware-detection claim is made. Watch bursts coalesce in a separate maximum-256-path debounce map; additional paths are dropped when that map is full, and notifications may be lost. Scheduled scans remain necessary and there is no per-event coverage guarantee. The work queue holds at most 256 paths with at most four analysis workers. Stop/shutdown cancels traversal and requests cooperative cancellation from the engine; an in-progress OS read can delay shutdown. Startup failure is exposed as nonzero SCM exit status.

The installer requires trusting the supplied binary and the administrative session. Service installation is an explicit security-sensitive administrator operation. The app does not install this service automatically and does not communicate with it. This is an optional local scanning component, not a complete antivirus product.
